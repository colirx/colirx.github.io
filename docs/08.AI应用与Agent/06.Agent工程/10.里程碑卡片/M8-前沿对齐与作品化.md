# M8 前沿对齐与作品化

**预计投入**：40 小时 +（持续型里程碑，不设硬性收口）
**标签**：`milestone` `agent` `math`
**入口条件**：M0–M7 至少 6 个已收口。

## 能力目标

把前七个里程碑的积累收成一个**可对外展示的工程作品**，
并具备独立读懂、复现前沿技术报告中工程组件的能力。
这是从"会做"到"能被前沿团队认可"的一步。

## 任务

1. **选方向并精读**：在 RL 训练 / 推理优化 / Agent 系统 三个方向里选一个，
   精读一篇前沿技术报告，把其中的一个**工程组件**复现出来（不必复现全部结果）。
   方向决定后，把该方向需要的数学概念补进 `docs/math-notes/`。
2. **作品化**：挑一个真实场景项目（优先选你单位里真在跑的东西，脱敏后），
   做完整：可安装、有 README、有评测数据、有架构说明。
3. **写工程复盘**：`docs/adr/M8-作品复盘.md`——哪些设计取舍是错的、当时为什么那么选、
   现在会怎么改。**这份文档比代码更能说明你的水平。**
4. **保持输出节奏**：每完成一个组件就写一篇 `docs/labs/` 报告，不攒到最后。

## 验证标准

- [ ] 复现的组件能跑通，且能说清与原实现的差异及原因。
- [ ] 作品仓库脱离你的机器能被他人跑起来（找一个人实测）。
- [ ] 作品有可量化的效果数据，不是"感觉变好了"。
- [ ] 能就作品做 30 分钟技术讲解，并回答"为什么不用 X 方案"这类问题。
- [ ] 复盘文档里至少有 3 条承认的错误判断。

## 数学 / 原理概念

依所选方向定，不预设。通用建议：

- **RL 方向**：期望回报、策略梯度、优势函数、KL 惩罚（只需直觉层）
- **推理优化方向**：数值精度、访存层级、并行策略（数据/张量/流水并行）
- **Agent 系统方向**：搜索、规划、可靠性工程、误差传播

原则不变：能用手上的代码解释它解决了什么问题，就算补上了。

## 外部资源（限 1 个）

- 依方向自选一篇**技术报告原文**（不是解读文章）——**用在任务 1**。
  解决的问题：训练你直接读一手资料的能力。二手解读会替你做掉最关键的判断，
  而那正是你需要练的部分。
