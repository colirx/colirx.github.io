# M1 检索质量工程

**预计投入**：30 小时
**标签**：`milestone` `agent` `eval` `math`
**入口条件**：M0 的评测执行器接口已定型。

## 能力目标

把"检索效果好像还行"变成一张可复现的对比表。完成后你能用数据决定：
文档怎么切、用哪个 embedding、要不要加重排，并说清每种选择付出的代价。

## 任务

1. **建评测集**：从你单位真实文档里出 40–60 条问题，每条标注标准答案与
   至少一段"黄金文档"。放进 `eval/datasets/`。这是整个里程碑里最费力也最值钱的一步。
2. **实现检索指标**：在 `src/eval/` 实现 `recall@k`、`MRR`、`nDCG`，
   跑出基线数字。**没有基线数字之前不要做任何调优。**
3. **做变量对比实验**：至少跑三组对照——切分粒度（如按段落 vs 按固定长度）、
   embedding 模型、是否重排。每组只改一个变量，结果记进 `docs/labs/M1-*.md`。
4. **落地结论**：把最优组合固化进 `src/retrieval/` 的默认配置，写一份 ADR 说明取舍依据
   （效果提升 vs 延迟/成本增加）。

## 验证标准

- [ ] `eval/datasets/` 里有 ≥40 条标注样例，且标注口径写在同目录 README 里。
- [ ] 一条命令能跑出完整的指标表，重复运行波动在可解释范围内。
- [ ] `docs/labs/` 里有一张横向对比表，包含效果与延迟两列，结论可直接引用。
- [ ] 能指出至少 2 个检索失败的典型案例，并说明失败原因（切分问题？embedding 问题？还是问题本身超出语料）。

## 数学 / 原理概念

- **相似度度量与归一化**：余弦、内积、欧氏距离在选择上的差异
- **排序与 Top-k**：为什么 recall@k 随 k 单调增，以及这意味着什么
- **召回与精确的权衡**：rerank 为什么能提升精度而不能提升召回上限
- **近似最近邻（ANN）直觉**：索引换速度，代价是什么

  常常不可迁移"，这会直接改变你在任务 3 里选择对比变量的方式。
