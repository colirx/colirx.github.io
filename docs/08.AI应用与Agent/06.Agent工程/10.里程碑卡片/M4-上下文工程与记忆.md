# M4 上下文工程与记忆

**预计投入**：35 小时
**标签**：`milestone` `agent` `math`
**入口条件**：M3 的轨迹日志已在持续产出数据。

## 能力目标

让 Agent 在长任务（几十上百轮）中不爆上下文、不丢关键信息、成本可预测。
完成后你能解释："同样一个长任务，为什么我的方案更便宜且没变笨。"

## 任务

1. **上下文预算器**：实现按预算装配上下文的策略——固定区（系统提示、工具定义）、
   可压缩区（历史轮次）、可按需取回区（外部记忆）。要求：超预算时行为可预测、可解释。
2. **压缩与裁剪策略对比**：至少实现两种（如滚动摘要、按相关性选轮次），
   在 M3 的任务集上做对照，记录信息保留率与成本。
3. **外部记忆**：把长期信息落盘到文件或数据库，实现写入时机与检索召回，
   并处理"记忆过期/错误记忆"的清理问题。
4. **长任务压测**：构造一个需要 50+ 轮的任务，对比"无管理"与"有管理"的表现与成本。

## 验证标准

- [ ] 50+ 轮任务中，上下文占用始终在上限内，且关键信息（前期约定、约束条件）未丢失。
- [ ] 压缩策略的对照组有数字：成本下降多少、任务成功率变化多少。
- [ ] 外部记忆的写入与召回有明确的触发规则，不是"每轮都塞进去"。
- [ ] 能画出自己方案的上下文构成图，并指出哪部分最费 token。

## 数学 / 原理概念

- **信息量与熵直觉**：为什么"摘要"必然丢信息，丢的是什么（可跳过，自测后决定）
- **注意力复杂度**：为什么上下文长度是平方级成本，这决定了预算策略的必要性
- **检索与生成的权衡**：塞进去 vs 让它去查，各自的风险
- **缓存与复用**：前缀缓存为什么能省钱，什么条件下失效
