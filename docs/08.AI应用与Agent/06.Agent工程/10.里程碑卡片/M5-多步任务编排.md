# M5 多步任务编排

**预计投入**：35 小时
**标签**：`milestone` `agent` `math`
**入口条件**：M3 的单 Agent 已稳定，M6 的最小埋点已能记录耗时与成本。

## 能力目标

能判断一个任务**该不该拆**，并用数据支撑这个判断。
完成后你不会因为"多 Agent 听起来更强"而拆，也不会因为"拆了麻烦"而不拆。

## 任务

1. **实现两种编排**：在 `src/agent/orchestration/` 实现（a）固定工作流的串并联，
   （b）planner–executor 式动态拆分。两者共用 M3 的循环与工具层。
2. **接真实场景任务**：选一个你工作中确实存在的多步骤任务（例如：从多份材料汇总一份报告、
   或跨系统核对数据），跑通两种编排。
3. **做单 Agent vs 多 Agent 的 A/B**：同一任务集上对比成功率、总 token、总耗时、失败模式差异。
   结论写进 `docs/labs/M5-*.md`，并写一份 ADR。
4. **定下拆分判据**：把你的结论固化成可复用的判断清单（什么样的任务值得拆），
   写进 `docs/adr/M5-拆分判据.md`。

## 验证标准

- [ ] 两种编排都能在真实任务上端到端跑通。
- [ ] A/B 对照有完整数字（成功率、token、耗时），不是主观感受。
- [ ] 能举出至少一个"拆了反而更差"的案例，并说清原因。
- [ ] 拆分判据清单能被同事直接拿去用，不需要你在旁边解释。

## 数学 / 原理概念

- **误差累积与组合可靠**：串联 5 个 95% 的步骤 vs 并联取多数，差别有多大
- **方差与稳定性**：为什么多 Agent 往往均值更高但方差也更大
- **并行与聚合**：并行收益的上限由什么决定
- **成本模型**：token 成本与延迟成本的换算关系
