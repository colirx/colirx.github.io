# M3 Agent 循环与工具调用

**预计投入**：40 小时
**标签**：`milestone` `agent` `math`
**入口条件**：M1 的检索能力与 M2 的结构化输出均可作为工具被调用。

## 能力目标

不依赖任何 Agent 框架，从零写出一个可控的 tool-calling 循环：
能规划、能选工具、能处理失败、能重试、能记账。
完成后你能看懂任何框架的 Agent 实现——因为你写过那个循环。

## 任务

1. **手写主循环**：在 `src/agent/loop.py` 实现"模型输出 → 解析工具调用 → 执行 →
   结果回填 → 继续"的循环。必须含：最大步数上限、单步超时、工具异常处理、整体预算控制。
2. **封装工具**：把 M1 的检索、M0 的生成、以及至少一个**真实工作场景**的工具
   （查数据库、读文件、调内部接口任选）统一成工具接口，写清每个工具的失败模式。
3. **全链路轨迹日志**：每一步记录：输入上下文摘要、模型输出、工具调用与结果、
   token 消耗、耗时。这是 M4 和 M6 的全部数据来源，**这一步不省**。
4. **压出边界**：构造 10 个刁钻任务（工具报错、需要连调两次、无解需要放弃、
   需要反问用户），跑一遍并修复暴露的问题。结果记入 `docs/labs/M3-*.md`。

## 验证标准

- [ ] 三类真实任务（单工具、多工具串联、需要放弃）各跑 10 次，成功率可量化。
- [ ] 工具报错时循环不崩，且能按策略重试或降级，日志里有据可查。
- [ ] 能准确说出一个典型任务消耗了多少 token、花在哪一步、为什么。
- [ ] 该 Agent 至少解决一个你在工作中**确实需要**的小任务，而非玩具任务。

## 数学 / 原理概念

- **状态机与终止条件**：为什么"最大步数"不是可选项
- **搜索空间与组合爆炸**：为什么步数一多，穷举就不成立
- **误差累积**：单步 95% 正确率，10 步之后是多少（可跳过，自测后决定——算一次就懂）
- **贝尔曼方程直觉**（可跳过，自测后决定）：只理解"当前决策要考虑未来收益"这一层，不做推导
