## 四、验收清单（写完自查）

- [ ] 给定一个失败会话 ID，能在 5 分钟内指认是检索 / 生成 / 工具哪一环（演练做过并计时）
- [ ] 一次 push 后 CI 自动跑完评测，并在 PR 上给出"哪些指标退化"的结论
- [ ] 看板能回答"上个月哪类任务最贵"，且数字与账单对得上
- [ ] 三类注入故障全部被 trace 捕获，无静默失败（逐类附上 trace 证据）
- [ ] 字段名与 OpenTelemetry GenAI 约定一致，没有自创同义字段
- [ ] 埋点之后建了看板——埋了不看的日志等于没埋

## 五、常见偷懒（自查是否犯）

- 只埋点不建看板——数据在库里躺着，出事时还是靠猜。
- 日志里没有可关联的 trace_id——跨环节一断链，5 分钟定位立刻变成不可能。
- 故障演练只做最简单的模型超时——工具脏数据和检索为空才是真会漏的那两类。
- 只看均值不看分布——P99 和方差不盯，退化会以"偶发卡顿"的形式溜过去。
- 阈值随手定（比如退化 1% 就红）——没有基线波动带支撑的阈值，只会让人习惯性忽略红灯。
