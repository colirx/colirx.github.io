## 五、常见偷懒（自查是否犯）

- 只测单并发就宣称"能支撑 X 并发"——单点数字对容量规划毫无价值。
- 只报平均延迟不报 P99——平均 800 ms 而 P99 8 s 的系统，用户感受就是"卡"。
- 把别人博客 / 论文里的吞吐当成自己的数据——方差全在硬件和参数里，那不是你的结论。
- 不记录硬件与软件版本——换个 llama.cpp commit 或驱动，数字可能差一倍，届时你无法解释。
