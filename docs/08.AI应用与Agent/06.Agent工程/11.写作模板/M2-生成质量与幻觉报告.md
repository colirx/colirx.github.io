## 四、验收清单（写完自查）

- [ ] judge 一致率是量化数字，不一致样例已入库——没校准过的 judge 分数不许引用
- [ ] 200 次连续调用解析失败率为 0（含重试后的最终成功率）
- [ ] ≥15 条失败案例写进 `docs/labs/M2-failures.md`，每条标注了归属环节
- [ ] 反幻觉手段既有提升数字，也有延迟 / 成本代价数字
- [ ] 报告里没有被 judge 分数单独支撑的结论（关键结论都有人工抽检佐证）

## 五、常见偷懒（自查是否犯）

- 直接信 judge 的分数，不做人工校准——那等于用一把没验证过的尺子量东西。
- 只统计成功案例、只截好看的输出——不写失败率的评测是宣传，不是报告。
- 把"回答更长了"当成"更完整了"——长度和完整性是两件事，judge 还专门偏袒长度。
- 单次运行就下结论——temperature > 0 时，一次结果什么都说明不了。
- 反幻觉只报效果不报代价——每加一条约束都可能更慢更贵，这必须写出来。
