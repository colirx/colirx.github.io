# 部署顺序与验收

> 本文是**3 节点测试集群**的实施顺序，不是生产安装手册。生产要补跨故障域、TLS、备份、资源隔离，见各选型页的"落地要点"。
> 原则：**每装一层，先验收，再装下一层**。不要一口气装完再排障。

## 总体节奏

| 阶段 | 内容 | 预计耗时 | 通过标准 |
| --- | --- | --- | --- |
| P0 | 三台宿主机体检与初始化 | 40 min | 内核、磁盘、内网、时间、出网正常 |
| P1 | kubeadm 三节点 + CNI | 60 min | 3 节点 Ready，跨节点 Pod 通 |
| P2 | 基础资源（OpenBao、Envoy Gateway、cert-manager） | 40 min | 密钥可读写，入口可访问 |
| P3 | 对象存储（SeaweedFS ×3）+ PostgreSQL 主备 | 60 min | S3 可读写，PG 可连 |
| P4 | Polaris + Iceberg | 40 min | Spark 能建表、写表、读表 |
| P5 | Kafka ×3 + Doris 3FE/3BE | 90 min | 3 broker 可生产消费，3 BE 可查询 |
| P6 | Spark + Flink | 40 min | 批任务、流任务都能提交 |
| P7 | DolphinScheduler | 30 min | 能跑通一个依赖 DAG |
| P8 | 治理与可观测（OpenMetadata、Prometheus 栈） | 40 min | 元数据可见，指标有数据 |
| P9 | 端到端链路 | 60 min | 一条 CDC 数据从 MySQL 落到 Doris |
| — | 缓冲 | 2 h | 排障、重装、写记录 |

三节点比单机多出"集群组装 + 副本打散 + 切主验证"的活，顺利的话 10–12 小时；首次搭建按 2 天准备更现实。如果只有 6 小时，只做 P0–P4，把"能写 Iceberg"这条线跑通。

## P0：宿主机初始化

> 云面板里的 `amd64` 就是 `x86_64`，本栈所有组件镜像都以 amd64 为主，放心选；如果是 ARM64（aarch64），才需要逐个确认镜像有没有 arm 版本。

```bash
# 1. 看家底
uname -a; lsb_release -a
nproc; free -h; df -hT; lsblk
ip addr; ip route

# 2. 时间必须准，否则证书、Kafka、Iceberg 都会出怪问题
timedatectl set-timezone Asia/Shanghai
timedatectl set-ntp true
timedatectl status

# 3. 出网与镜像源
curl -I https://registry.aliyuncs.com/v2/
curl -I https://registry-1.docker.io/v2/

# 4. 关 swap（kubelet 要求）
swapoff -a
sed -ri '/\sswap\s/s/^#?/#/' /etc/fstab

# 5. 内核模块与转发
modprobe overlay; modprobe br_netfilter
cat >/etc/modules-load.d/k8s.conf <<'EOF'
overlay
br_netfilter
EOF
cat >/etc/sysctl.d/99-k8s.conf <<'EOF'
net.bridge.bridge-nf-call-iptables=1
net.bridge.bridge-nf-call-ip6tables=1
net.ipv4.ip_forward=1
fs.inotify.max_user_instances=8192
fs.inotify.max_user_watches=524288
EOF
sysctl --system
```

**验收**：`free -h` 无 swap；`sysctl net.ipv4.ip_forward` 为 1；`curl -I` 返回 200/301。

**数据盘**（三台一样，先决定存储方案）：

> - 用 **SeaweedFS**：数据盘格式化为 `/data`，给容器运行时、local-path、SeaweedFS 用。
> - 用 **Ceph**：数据盘**保持裸盘、不格式化**，留给 Rook/OSD；kubeadm 与镜像放系统盘（镜像总量控制在 20 GB 内）。

```bash
# 仅在用 SeaweedFS 时执行；用 Ceph 就跳过
lsblk -f                      # 确认盘符，别格式化错盘！
mkfs.ext4 /dev/vdb
mkdir -p /data
echo '/dev/vdb /data ext4 defaults,noatime 0 0' >> /etc/fstab
mount -a
df -h /data
```

## P1：kubeadm 完整 K8s（2026-10-17 实测）

> k3s 是轻量发行版；本次按要求改用**上游 kubeadm**。完整踩坑与镜像源结论见 [实战记录](../04.实战记录.md)。
> 结构：node1 = control-plane，node2/node3 = worker；1 个控制面足够测试，HA 控制面需要 VIP/LB，另议。

### 1. 三台通用基础包

```bash
# containerd（Ubuntu 22.04 源是 2.2.x，够新）
apt-get update
apt-get install -y containerd apt-transport-https ca-certificates curl gpg
containerd config default > /etc/containerd/config.toml
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sed -i "s#sandbox = '.*'#sandbox = 'registry.aliyuncs.com/google_containers/pause:3.10.2'#" /etc/containerd/config.toml
systemctl enable --now containerd

# Docker Hub 镜像加速：containerd 用 certs.d，不是 /etc/docker/daemon.json
# 关键：config_path 必须是单个目录；写成 a:b 会被忽略
sed -i "s|config_path = '/etc/containerd/certs.d:/etc/docker/certs.d'|config_path = '/etc/containerd/certs.d'|" /etc/containerd/config.toml
mkdir -p /etc/containerd/certs.d/docker.io
cat > /etc/containerd/certs.d/docker.io/hosts.toml <<'EOF'
server = "https://docker.1ms.run"
[host."https://dockerproxy.net"]
  capabilities = ["pull", "resolve"]
EOF
systemctl restart containerd

# 系统盘只有 20G 时，把 containerd 数据挪到 /data（200G 盘）
systemctl stop kubelet containerd 2>/dev/null || true
mkdir -p /data/containerd
cp -a /var/lib/containerd/. /data/containerd/
sed -i "s|^root = .*|root = '/data/containerd'|" /etc/containerd/config.toml
systemctl start containerd

# K8s 包：阿里云源（pkgs.k8s.io 国内慢/会 302）
mkdir -p /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/kubernetes-new/core/stable/v1.37/deb/Release.key \
  | gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://mirrors.aliyun.com/kubernetes-new/core/stable/v1.37/deb/ /' \
  > /etc/apt/sources.list.d/kubernetes.list
apt-get update
apt-get install -y kubelet kubeadm kubectl
apt-mark hold kubelet kubeadm kubectl
```

### 2. node1 初始化控制面

```bash
# 关键：不要用默认 registry.k8s.io，它会 302 到 Google pkg.dev 超时
kubeadm config images pull \
  --image-repository=registry.aliyuncs.com/google_containers \
  --kubernetes-version=v1.37.1

kubeadm init \
  --apiserver-advertise-address=<node1-ip> \
  --control-plane-endpoint=<node1-ip> \
  --pod-network-cidr=10.244.0.0/16 \
  --kubernetes-version=v1.37.1 \
  --image-repository=registry.aliyuncs.com/google_containers \
  --cri-socket unix:///run/containerd/containerd.sock

mkdir -p /root/.kube
cp -f /etc/kubernetes/admin.conf /root/.kube/config
export KUBECONFIG=/root/.kube/config
```

### 3. 装 CNI（Calico）

Flannel 依赖 `ghcr.io` 多架构镜像，国内拉取极慢；改用 Calico（Docker Hub 镜像）：

```bash
curl -fsSL https://raw.githubusercontent.com/projectcalico/calico/v3.30.3/manifests/calico.yaml -o /root/calico.yaml
# Calico 默认 IPPool 是 192.168.0.0/16，必须改成 kubeadm 的 10.244.0.0/16
sed -i 's#192.168.0.0/16#10.244.0.0/16#g' /root/calico.yaml
kubectl apply -f /root/calico.yaml
kubectl -n kube-system get pods -l k8s-app=calico-node -w
```

> 单网卡环境默认 `first-found` 一般能选对 eth0；如果 calico-node 选错网卡，给 DaemonSet 加
> `IP_AUTODETECTION_METHOD=interface=eth0`。

> **镜像拉取的两个坑**：
> 1. `:latest` 默认 `imagePullPolicy: Always`，本地有镜像也会强制回源，表现为 `ImagePullBackOff`；测试用固定 tag，或显式 `IfNotPresent`。
> 2. 大镜像（如 `calico/node` 150MB）在 0.4–1.3MB/s 的代理上很慢；同网段节点之间用 `scp` 传 tar + `ctr import` 更快，不要走 Windows 中转。

### 4. node2/node3 加入

```bash
# node1 上生成 join 命令
kubeadm token create --print-join-command

# node2/node3 上执行（示例）
kubeadm join <node1-ip>:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

### 5. 验证

```bash
kubectl get nodes -o wide          # 3 个 Ready
kubectl -n kube-system get pods    # calico-node 每节点 1 个 Running
kubectl run test-$RANDOM --image=registry.aliyuncs.com/google_containers/pause:3.10.2 --restart=Never
kubectl get pod -o wide            # 能调度到 worker
```

## P1-备选：k3s（轻量，不推荐）

> 以下为原 k3s 方案，保留作对比；本次不采用。

### node1：初始化 etcd 集群

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_MIRROR=cn sh -s - server \
  --cluster-init \
  --write-kubeconfig-mode 644 \
  --disable traefik \
  --data-dir /data/k3s \
  --node-ip <node1私网IP> \
  --advertise-address <node1私网IP> \
  --tls-san <node1私网IP> \
  --tls-san <node1公网IP>

# 取加入 token
cat /var/lib/rancher/k3s/server/node-token
```

### node2 / node3：加入集群

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_MIRROR=cn K3S_TOKEN=<token> sh -s - server \
  --server https://<node1私网IP>:6443 \
  --write-kubeconfig-mode 644 \
  --disable traefik \
  --data-dir /data/k3s \
  --node-ip <本机私网IP> \
  --advertise-address <本机私网IP>
```

```bash
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
kubectl get nodes -o wide
kubectl -n kube-system get pods
```

- 三台都是 server（control plane + worker），etcd 自动组成三节点；挂一台仍可读写。
- **用 Ceph 时删掉 `--data-dir /data/k3s`**（数据盘是裸盘，没有 `/data`），改用系统盘默认目录。
- `--node-ip` 必须写私网 IP，别让 k3s 选到公网网卡。
- `--disable traefik`：入口统一用 Envoy Gateway，别两套 ingress 打架。
- kubeconfig 默认指向 node1；node1 挂了就把 `server:` 改成 node2/node3 的私网 IP。
- 如果公网 IP 变了，记得补 `--tls-san`，否则 kubectl 证书报错。

### 打标签与打散

```bash
kubectl label node node1 node2 node3 topology.kubernetes.io/zone=test
```

> 测试集群**不要**给控制面打 `NoSchedule`，让业务 Pod 也跑上去；用 ResourceQuota 给系统组件留资源。生产才做 master/worker 分离。

命名空间一次建好：

```bash
for ns in security gateway storage data catalog compute schedule query governance monitoring; do
  kubectl create namespace $ns
done
```

**验收**：`kubectl get nodes` 为 `Ready`；能起一个 `busybox` Pod 并 `nslookup kubernetes.default`。

## P3：对象存储与 PostgreSQL

### SeaweedFS

```bash
helm repo add seaweedfs https://seaweedfs.github.io/seaweedfs/helm
helm install seaweedfs seaweedfs/seaweedfs -n storage -f seaweedfs-values.yaml
```

`seaweedfs-values.yaml`（3 节点分布式，示意，字段以 chart 版本为准）：

```yaml
master:
  enabled: true
  replicas: 3
volume:
  enabled: true
  replicas: 3
  sizeLimit: 80Gi
filer:
  enabled: true
  replicas: 2
s3:
  enabled: true
  replicas: 2
  enableAuth: true
```

> 默认调度可能把副本挤到同一台，给 master/volume 配 `podAntiAffinity`（topologyKey: `kubernetes.io/hostname`），否则"3 副本"没有意义。

建桶（用 filer 的 `weed shell` 或 S3 API）：

```bash
kubectl -n storage exec -it deploy/seaweedfs-filer -- weed shell
# 在 shell 里：
#   s3.bucket.create -name warehouse
#   s3.bucket.list
```

**验收**：用 `aws s3 ls --endpoint-url http://seaweedfs-s3.storage:8333` 能列出 `warehouse`；上传/下载一个文件成功。

## P4：Polaris + Iceberg

安装 Polaris（Helm 或官方 quickstart），关键配置：

- 元数据库指向 `polaris` 库；
- 设置 bootstrap 的 root principal（client id / secret）；
- `POLARIS_REALM` 用一个环境一个，POC 用 `POLARIS`。

建 catalog（用 management API 或 Polaris Admin UI）：

```json
{
  "catalog": {
    "name": "lake",
    "type": "INTERNAL",
    "readOnly": false,
    "properties": {
      "default-base-location": "s3://warehouse/lake"
    }
  },
  "storageConfigInfo": {
    "storageType": "S3",
    "allowedLocations": ["s3://warehouse/lake"]
  }
}
```

> 不同版本的字段名略有差异，S3 endpoint、path-style、AK/SK 的填法以官方 quickstart 为准。核心是三件事：**endpoint 指向 SeaweedFS、开 path-style、warehouse 前缀与 bucket 对齐**。

**验收**：Spark 里执行

```sql
CREATE NAMESPACE IF NOT EXISTS lake.ods;
CREATE TABLE lake.ods.orders (id BIGINT, amount DECIMAL(18,2), ts TIMESTAMP)
  USING iceberg;
INSERT INTO lake.ods.orders VALUES (1, 9.9, current_timestamp());
SELECT * FROM lake.ods.orders;
```

能建、能写、能读，且 `s3://warehouse/lake/ods/orders/` 下出现 `metadata/` 与 `data/`。

## P5：Kafka 与 Doris

### Kafka（Strimzi，KRaft 三节点）

```bash
helm repo add strimzi https://strimzi.io/charts/
helm install strimzi-operator strimzi/strimzi-kafka-operator -n data
```

```yaml
apiVersion: kafka.strimzi.io/v1beta2
kind: KafkaNodePool
metadata:
  name: dual-role
  labels:
    strimzi.io/cluster: demo
spec:
  replicas: 3
  roles: [controller, broker]
  storage:
    type: jbod
    volumes:
      - id: 0
        type: persistent-claim
        size: 20Gi
        deleteClaim: false
  template:
    podAntiAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              strimzi.io/cluster: demo
          topologyKey: kubernetes.io/hostname
---
apiVersion: kafka.strimzi.io/v1beta2
kind: Kafka
metadata:
  name: demo
  annotations:
    strimzi.io/node-pools: enabled
spec:
  kafka:
    listeners:
      - name: plain
        port: 9092
        type: internal
        tls: false
    config:
      offsets.topic.replication.factor: 3
      transaction.state.log.replication.factor: 3
      transaction.state.log.min.isr: 2
      default.replication.factor: 3
      min.insync.replicas: 2
  entityOperator:
    topicOperator: {}
    userOperator: {}
```

> 3 个 broker 必须跨节点；anti-affinity 写错会全挤在一台，`RF=3` 就成了摆设。建 topic 时也显式写 `--replication-factor 3`。

**验收**：

```bash
kubectl -n data get pods -l strimzi.io/cluster=demo
# 节点池的 Pod 名形如 demo-dual-role-0/1/2
kubectl -n data exec -it demo-dual-role-0 -- \
  bin/kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic test --partitions 3 --replication-factor 3
kubectl -n data exec -it demo-dual-role-0 -- \
  bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic test
# 另一个终端消费；再 describe topic 确认 ISR=3
```

### Doris

用 Doris Operator 或 Helm chart，三节点配置：

- FE 3 副本（1 leader + 2 follower），BE 3 副本；
- FE 用 local-path 10Gi，BE 用 local-path 50Gi；
- BE 内存上限 6Gi，`storage_root_path` 指向 PVC；
- FE/BE 都要配 `podAntiAffinity`，按节点打散。

> 如果只想先跑通，1 FE + 3 BE 也能验证查询与副本；但 FE 少于 3 个就没有选主可验。

**验收**：

```bash
mysql -h <doris-fe> -P 9030 -u root
> SHOW BACKENDS;   -- 3 个 Alive: true，分布在 3 台
> CREATE DATABASE demo;
> CREATE TABLE demo.t (id INT) DUPLICATE KEY(id) DISTRIBUTED BY HASH(id) BUCKETS 3;
> INSERT INTO demo.t VALUES (1);
> SELECT * FROM demo.t;
```

## P9：端到端验收

最小闭环：

```
MySQL（开 binlog）
  └─ Flink CDC → Kafka topic cdc.orders
       └─ Flink SQL → Iceberg lake.ods.orders
            └─ Spark SQL → lake.dws.orders_daily
                 └─ Doris 外部 Catalog 查询
                      └─ MySQL 客户端（模拟 BI）出结果
```

验收点：

- [ ] MySQL 插入一行，10 秒内 Kafka 能看到变更事件
- [ ] Flink 作业无重启，checkpoint 持续成功
- [ ] Iceberg 表出现新快照，`SELECT count(*)` 增加
- [ ] Spark 聚合结果正确，分区按天生成
- [ ] Doris 通过 Iceberg 外表查到同一份数据
- [ ] DolphinScheduler 能把上面几步串成一个 DAG，失败能单步重跑
- [ ] OpenMetadata 能看到 `ods.orders → dws.orders_daily` 的血缘
- [ ] Grafana 能看到 Kafka lag、Flink checkpoint、Doris QPS
- [ ] 杀掉一个 Flink TaskManager，作业自动恢复
- [ ] 杀掉一个 Kafka broker，生产消费不中断
- [ ] 杀掉一个 Doris BE，查询仍能返回

## 测试集群的已知偏差

| 项 | 生产 | 测试集群 | 影响 |
| --- | --- | --- | --- |
| 对象存储 | Rook + Ceph RGW，3 副本/EC，独立故障域 | SeaweedFS 3 节点或 Ceph 3 OSD | 验证不了真实磁盘故障与 PB 级 |
| 镜像仓库 | Harbor 多副本 | 公网镜像 + 加速 | 生产要补 |
| Kafka | 3 broker，RF=3，跨机柜 | 3 broker，RF=3，同机房 | 验证不了机柜/机房级故障 |
| Doris | 多 FE + 多 BE，存算分离 | 3 FE + 3 BE，存算一体 | 验证不了大规模并发 |
| Elasticsearch | 多节点、开安全 | 单节点、关安全 | 生产必须补认证与 TLS |
| 入口 | 云 LB + WAF + TLS | NodePort + SSH 隧道 | 生产要补 |
| 高可用 | 跨 AZ / 同城双活 | 单机房 3 节点 | 验证不了站点级 DR |
