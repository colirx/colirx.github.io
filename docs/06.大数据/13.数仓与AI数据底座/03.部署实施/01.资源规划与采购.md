# 资源规划与采购

> 这一页解决“买几台、买多大、下单前确认什么”，不绑定具体云厂商和价格。

## 1. 先定拓扑

这套平台的最低形态是 **3 台 K8s 节点**：

```text
node1  control-plane + 部分工作负载
node2  worker
node3  worker
```

为什么不买单机：

- 单机跑 K8s 没有跨节点调度、副本、故障域；
- Kafka/SeaweedFS 的“3 副本”在单机上没有意义；
- 后续加节点、做 HA 都没有基础。

3 台是“能验证真集群”的最低配，不是生产推荐。

## 2. 规格怎么估

### 2.1 CPU

| 组件 | 建议 |
| --- | --- |
| K8s + 系统 | 2C |
| Flink JM/TM | 4C |
| Doris FE/BE | 4–8C |
| DS/OM/Harbor/SHS | 2–4C |
| 余量 | 2C |

16C/台是测试环境比较稳的起点；8C 只能做功能验证，跑 1M 数据会紧。

### 2.2 内存

| 组件 | 建议 |
| --- | --- |
| K8s + 系统 | 2–4G |
| Flink | 6–8G |
| Doris | 8–16G |
| DS/OM/OpenSearch | 6–8G |
| Kafka/MySQL/PG | 4–6G |
| 余量 | 4G |

32G/台能同时跑；16G/台需要错峰启动。

### 2.3 磁盘

| 用途 | 大小 |
| --- | --- |
| 系统盘 | 40–100G |
| 数据盘 | 200G 起 |
| 镜像/日志 | 至少留 50G |

数据盘建议单独挂到 `/data`，containerd、PVC、Iceberg 临时文件都放这里。

### 2.4 带宽

- 拉镜像、传数据、看 UI 都需要带宽；
- 测试环境 100M 会明显快于 5M；
- 生产按日增量和备份窗口估，不要只看 UI。

## 3. 3 台还是 5 台

| 拓扑 | 适合 |
| --- | --- |
| 3 × 16C32G | 功能验证、1M 数据、单控制面 |
| 5 × 16C32G | 想验证多节点/双故障/HA |
| 3 × 8C16G | 只跑最小链路，容易 OOM |

建议先 3 台跑通，再决定是否扩 5 台。不要一开始买 5 台 16G。

## 4. 存储方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| local-path | 简单、快 | 无副本，节点挂数据不可用 |
| SeaweedFS | S3 兼容、部署简单 | 需要维护 volume/master |
| Rook + Ceph | 真分布式、副本 | 部署慢、对裸盘要求高 |

测试环境推荐 **local-path + SeaweedFS**；生产再评估 Ceph 或云对象存储。

## 5. 下单前检查清单

- [ ] 三台在同一个 VPC/内网，能互通；
- [ ] 有公网 IP 或跳板机；
- [ ] 数据盘是裸盘，能自己格式化；
- [ ] CPU 支持 AVX2（Doris BE 需要）；
- [ ] 安全组能放行 NodePort；
- [ ] 确认关机是否计费、是否支持快照；
- [ ] 确认实例释放后公网 IP 是否保留；
- [ ] 确认带宽是独享还是峰值。

## 6. 成本估算方法

不要抄某个厂商的价格，按下面公式估：

```text
每天成本 =
  三台实例单价 × 3
  + 数据盘单价 × 总容量
  + 带宽/流量费
  + 快照/镜像存储费
```

测试环境按天计费，跑完即释放；需要保留时再做快照或导出。

## 7. 扩容路径

```text
3 台功能验证
  → 加 2 台 worker（5 台）
  → control-plane 扩到 3 台
  → 数据面做多副本
  → 生产 HA
```

不要在第 1 天就追求 3 control-plane + 3 FE + 3 BE；先把链路跑通，再按瓶颈扩。
